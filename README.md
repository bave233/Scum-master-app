# Scum Master App

แอปสำหรับวางแผนกำลังทีมใน Sprint และดู Development Timeline ทั้งปี ใช้งานบนเครื่องของตัวเองผ่านเว็บหรือ macOS app โดยเชื่อม Jira เพื่อดูงานของสมาชิกและ Manday ที่วางแผนไว้

## ทำอะไรได้บ้าง

- สร้างและลบ Sprint โดยเลือกวันเริ่มต้น–สิ้นสุดเอง ไม่บังคับว่าต้องเป็นสองสัปดาห์
- แบ่งสมาชิกเป็น `iOS`, `Android` หรือ `QA` และดูผลรวมของแต่ละ Platform กับทั้งทีม
- คำนวณ Available MD จากวันทำงาน จัดการวันหยุดไทย/วันหยุดบริษัท และบันทึกวันลาครึ่งวันหรือเต็มวันเป็นวันเดียวหรือช่วงวัน
- Sync sub-task จาก Jira เพื่อดูชื่อ Ticket, สถานะ, Story Point และ Manday ของคนที่เพิ่มไว้ในทีม
- ดูปฏิทินทั้งปีพร้อม Sprint, วันหยุด, Timeline ของโปรเจกต์, Freeze code, Release, Hotfix และเวอร์ชันที่ปล่อย
- Import/Export Sprint ด้วย Excel และ Import Timeline ของโปรเจกต์จาก CSV
- สำรอง ย้ายเครื่อง หรือล้างข้อมูลผ่าน Settings

## ติดตั้งและเปิดใช้งาน

ต้องมี **Node.js 22.13 ขึ้นไป** และ npm จากนั้นที่โฟลเดอร์โปรเจกต์ให้รัน:

```bash
npm install
npm run dev
```

เปิด URL ที่แสดงใน Terminal หลังสั่ง `npm run dev`

บน macOS สามารถสร้างตัวเปิดแอปแล้วดับเบิลคลิก `Scum Master App.app` ได้:

```bash
npm run app:build
```

วาง `Scum Master App.app` ไว้ข้าง `package.json` เสมอ ตัวแอปจะเปิด local server ให้อัตโนมัติและหยุดเมื่อปิดแอป หลัง clone ลงเครื่องใหม่ให้รัน `npm install` และ `npm run app:build` บนเครื่องนั้น

## เริ่มใช้งานครั้งแรก

1. กด **+ Sprint** ใส่ชื่อ Sprint ให้ตรงกับ Jira เลือกวันเริ่มต้น–สิ้นสุด และกำหนดอัตรา `1 SP = กี่ MD` สำหรับข้อมูลใน Excel
2. กดไอคอน **Settings → ตั้งค่าการเชื่อมต่อ Jira** แล้วกรอก Jira URL, email, API token และชื่อ/ID ของ Story Point field
3. ไปที่แท็บ **สมาชิกและวันลา** กด **+ สมาชิก** เลือก Platform แล้วค้นหาและเพิ่มผู้ใช้จาก Jira ระบบใช้ `accountId` เพื่อจับคู่งาน
4. เพิ่มวันลาและตรวจสอบวันหยุดตามต้องการ จากนั้นกด **Sync Jira** ใน Sprint ที่เลือก

ต้องเชื่อมต่ออินเทอร์เน็ตและมีสิทธิ์อ่าน Ticket, Comment และค้นหาผู้ใช้ใน Jira สำหรับการ Sync; ข้อมูลที่ Sync ล่าสุดยังดูได้เมื่อออฟไลน์

## Capacity และ Jira effort

หน้า **Capacity** แสดง `TEAM CAPACITY`, `JIRA EFFORT` และ `REMAINING` แยกตาม Platform พร้อม Summary ทั้งทีม ส่วนตารางรายคนแสดง Available, วันลา, งาน Jira, Workload และ Remaining

| ค่า | วิธีคิด |
| --- | --- |
| Available MD | วันจันทร์–ศุกร์ในช่วง Sprint − วันหยุดที่เปิดใช้งาน − วันลาที่ตรงกับวันทำงาน |
| Jira effort / Planned MD | ผลรวม Manday ที่อ่านได้จาก Comment ของ sub-task ที่มอบหมายให้สมาชิก |
| Remaining MD | Available MD − Planned MD |
| Workload | Planned MD ÷ Available MD × 100% |

แอปอ่าน sub-task ที่มี `[iOS]`, `[Android]` หรือ `[QA]` ในชื่อ โดย Comment ที่เป็น Manday ต้องมีข้อความ **`MD: 1.5`** ตามรูปแบบนี้ทั้งคอมเมนต์ (รองรับทศนิยม) ระบบใช้ค่าจาก Comment ที่ตรงรูปแบบล่าสุด หากยังไม่มี `MD:` งานนั้นจะยังปรากฏในรายการ แต่คิดเป็น **0 MD**; Story Point แสดงแยกต่างหากและไม่ถูกนำมาคิดแทน MD กดตัวเลข Jira effort เพื่อดูชื่อและสถานะ Ticket แล้วกดรหัส Ticket เพื่อเปิด Jira

## สมาชิก วันลา และวันหยุด

- สมาชิกเพิ่มได้หลายคน เลือกหรือเปลี่ยน Platform ได้ และลบออกได้
- วันลาเลือกหนึ่งวันหรือช่วงวัน โดยระบุเต็มวันหรือครึ่งวัน เพิ่มหลายรายการต่อคนได้ แต่ไม่อนุญาตให้บันทึกวันที่ซ้ำ
- แท็บ **วันหยุด** ดึงวันหยุดไทยเมื่อออนไลน์ ปิดวันหยุดที่ทีมไม่หยุดจริง หรือเพิ่ม/ลบวันหยุดบริษัทเองได้ โดยเพิ่มวันที่ซ้ำไม่ได้
- วันหยุดและวันลาที่ตรงกับวันเสาร์–อาทิตย์หรือวันหยุดอื่นอยู่แล้วจะไม่ถูกหักจาก Available MD ซ้ำ

## Timeline ทั้งปี

แท็บ **Timeline ทั้งปี** แสดงปฏิทินรายปีและช่วง Sprint กด **+ เพิ่ม Timeline** เพื่อใส่ Title, ช่วงวัน, Epic link และสี แต่ละช่วงซ้อนทับกันได้ คลิกช่วงงานเพื่อแก้ไขหรือลบ

วง **Freeze code** และ **Release** กับลูกศร Regression/QA อยู่ในปฏิทินโดยตรง ลากวงไปวันใหม่หรือคลิกเพื่อแก้วันที่และเวอร์ชันได้ ตั้งค่าวัน Release ตั้งต้น เวอร์ชันตั้งต้น และจำนวนวันต่อรอบใน Settings; เวอร์ชัน Release ถัดไปจะเพิ่มเลข minor อัตโนมัติเมื่อไม่ได้กำหนดเอง คลิกวันที่ว่างเพื่อเพิ่ม **Hotfix** พร้อมเวอร์ชันพิเศษโดยไม่เปลี่ยนรอบ Release ปกติ

วันหยุดที่เปิดใช้งานจะแสดงในปฏิทินด้วย หากวันหยุดตรงกับ Release ช่องวันเป็น **สีเหลือง**; หากตรงกับ Freeze ช่องวันเป็น **สีน้ำเงิน**

### Import Timeline จาก CSV

กด **Import Timeline** ในแท็บ Timeline ตั้งชื่อโปรเจกต์แล้วเลือกไฟล์ `.csv` ไฟล์ต้องมีคอลัมน์ `Task Name`, `Actual Start Date` และ `Actual End Date` โดยวันที่เป็น `DD/MM/YYYY` แอปจะนำเข้าเฉพาะแถวที่ชื่อมี keyword ที่กำหนดใน Settings (ค่าเริ่มต้น `mobile,ios,android,app`) และมีช่วงวันที่ถูกต้อง งานของโปรเจกต์จะแสดงรวมใต้ชื่อโปรเจกต์; กดปุ่มลบที่กรอบโปรเจกต์เพื่อลบ Timeline ทั้งโปรเจกต์

## Excel, Backup และข้อมูลในเครื่อง

- ปุ่ม **Export** ดาวน์โหลด Excel `.xlsx` ของ Sprint ที่เลือก; ปุ่ม **Import Sprint** นำไฟล์รูปแบบเดียวกันกลับมาอัปเดต Sprint เดิม โดยอ้างอิง `Sprint ID` ในไฟล์ ตรวจสอบไฟล์ก่อนยืนยันเพราะข้อมูลของ Sprint เดิมจะถูกแทนที่
- ใน **Settings → ดาวน์โหลด Backup** จะได้ไฟล์ JSON รวมสมาชิก, Sprint, วันหยุด, วันลา, Jira effort ที่ Sync ไว้, Timeline และการตั้งค่า **ไม่รวม Jira API token**
- **Restore Backup** จะแทนข้อมูลแอปปัจจุบันทั้งหมดด้วยข้อมูลในไฟล์ ส่วน Jira token ต้องกรอกใหม่หลัง Restore
- **ล้างข้อมูลทั้งหมด** จะลบข้อมูลรวมถึง Jira token แล้วกลับเป็นค่าเริ่มต้น ควรดาวน์โหลด Backup ก่อน

ข้อมูลถาวรทั้งหมดอยู่ใน `app-data/` บนเครื่อง รวมถึง Jira API token ในฐานข้อมูล local **อย่าอัปโหลดโฟลเดอร์นี้หรือไฟล์ Backup ที่มีข้อมูลทีมขึ้น Git สาธารณะ** `.gitignore` กัน `app-data/`, `node_modules/`, `.wrangler/` และไฟล์ build หลักไว้แล้ว ส่วน `Scum Master App.app/` เป็นไฟล์ build ที่สร้างใหม่ได้ หากไม่ต้องการอัปขึ้น Git ให้เพิ่ม `/Scum Master App.app/` ใน `.gitignore` ก่อน `git add .`

## สำหรับผู้พัฒนา

```bash
npm run lint
npm test
npm run build
```

โค้ดหลักอยู่ใน `app/` และ `lib/`; โครงสร้างฐานข้อมูลกับ migration อยู่ใน `db/` และ `drizzle/`; ตัวเปิด macOS อยู่ใน `macos/` และ `scripts/` ชื่อแอปและชื่อเจ้าของลิขสิทธิ์ถูกกำหนดไว้กับโปรเจกต์ ไม่ใช่ค่าที่เปลี่ยนใน Settings
